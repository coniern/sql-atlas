# 13 · 方言差异速查：SQLite / MySQL / PostgreSQL / SQL Server

> 一句话：SQL 标准只是下限，四个数据库各有各的"方言税"。这章是迁移和面试时的速查表。

## 13.1 为什么会有方言

SQL:2016 标准覆盖核心语法，但窗口函数帧、UPSERT、JSON 操作这些"日常刚需"各库实现时间和语法都不同。**写可迁移 SQL 的策略：只用标准语法 + 把方言锁在 ORM 层（第 12 章的 Dialect 就是为此存在）。**

## 13.2 类型系统对照

| 语义 | SQLite | MySQL | PostgreSQL | SQL Server |
|---|---|---|---|---|
| 整数 | INTEGER | INT/BIGINT | INTEGER/BIGINT | INT/BIGINT |
| 精确小数 | ⚠ NUMERIC 会退化成浮点 | DECIMAL | NUMERIC | DECIMAL |
| 自增主键 | INTEGER + AUTOINCREMENT | AUTO_INCREMENT | SERIAL / GENERATED | IDENTITY(1,1) |
| 布尔 | INTEGER 0/1 | TINYINT(1) | BOOLEAN | BIT |
| 时间 | TEXT/INTEGER（无原生类型） | DATETIME | TIMESTAMP | DATETIME2 |
| JSON | TEXT + JSON 函数 | JSON | JSONB（可索引）★ | NVARCHAR + OPENJSON |
| 大文本 | TEXT | TEXT | TEXT | NVARCHAR(MAX) |

两个著名的坑：
- **金额用 DECIMAL**：SQLite 的 NUMERIC 存出来还是 IEEE 浮点 —— 用整数存分（第 3 章）
- **PG 的 JSONB 可建索引、可高效查询**，是四个库里 JSON 能力最强的

## 13.3 常用函数对照

| 功能 | SQLite | MySQL | PostgreSQL | SQL Server |
|---|---|---|---|---|
| 当前时间 | `datetime('now')` | `NOW()` | `NOW()` | `GETDATE()` |
| 字符串拼接 | `\|\|` 或 concat | `CONCAT()` | `\|\|` 或 CONCAT | `+` 或 CONCAT |
| 取年份 | `strftime('%Y', d)` | `YEAR(d)` | `EXTRACT(YEAR FROM d)` | `YEAR(d)` |
| 类型转换 | `CAST(x AS INTEGER)` | `CAST()` | `CAST()` / `::` | `CAST()` |
| 空值默认 | `IFNULL(a,b)` / `COALESCE` | `IFNULL` / COALESCE | COALESCE | ISNULL / COALESCE |
| 字符串长度 | `LENGTH(s)` | `CHAR_LENGTH(s)` | `LENGTH(s)` | `LEN(s)` |
| 日期加 1 天 | `date(d,'+1 day')` | `DATE_ADD(d, INTERVAL 1 DAY)` | `d + INTERVAL '1 day'` | `DATEADD(day,1,d)` |

## 13.4 分页与取前 N

```sql
-- 标准写法（四库通用）
SELECT * FROM orders ORDER BY order_id LIMIT 10 OFFSET 20;

-- SQL Server 老版本（2012 前）要用 TOP + 子查询，2012+ 支持 OFFSET：
SELECT * FROM orders ORDER BY order_id OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY;
```

深分页（`LIMIT 100000, 10`）在所有库上都是灾难 —— 需要扫过前 10 万行。**用游标分页替代：`WHERE order_id > 最后看到的id ORDER BY order_id LIMIT 10`，任何偏移量都是 O(log n)。**

## 13.5 UPSERT（存在则更新，不存在则插入）

```sql
-- SQLite（3.24+）/ PostgreSQL
INSERT INTO products (sku, price) VALUES ('SKU001', 99)
ON CONFLICT (sku) DO UPDATE SET price = excluded.price;

-- MySQL
INSERT INTO products (sku, price) VALUES ('SKU001', 99)
ON DUPLICATE KEY UPDATE price = VALUES(price);

-- SQL Server
MERGE INTO products WITH (HOLDLOCK) AS t
USING (VALUES ('SKU001', 99)) AS s(sku, price) ON t.sku = s.sku
WHEN MATCHED THEN UPDATE SET price = s.price
WHEN NOT MATCHED THEN INSERT (sku, price) VALUES (s.sku, s.price);
```

同一个语义，三种写法 —— 这就是"方言税"的典型样子。

## 13.6 能力矩阵：谁有什么

| 能力 | SQLite | MySQL | PostgreSQL | SQL Server |
|---|---|---|---|---|
| 窗口函数 | 3.25+ | 8.0+ | ✓ | 2012+ |
| 递归 CTE | 3.8.3+ | 8.0+ | ✓ | 2005+ |
| `FULL OUTER JOIN` | ✗ | ✗（8.0 仍无） | ✓ | ✓ |
| `RETURNING` | 3.35+ | ✗ | ✓ | ✗（用 OUTPUT） |
| STRICT 类型检查 | 3.37+ | 部分 | ✓（默认严格） | ✓ |
| 部分索引 `WHERE` | ✓ | ✗ | ✓ | ✗（用过滤索引 ✓） |
| 库内全文检索 | FTS5 | FULLTEXT | tsvector | 全文目录 |
| 嵌套事务 | ✗ | ✗ | SAVEPOINT | SAVEPOINT |
| 并发模型 | 库级写锁 | 行锁（InnoDB） | MVCC | 行锁 + 快照 |

几个反直觉的点：

1. **SQLite 不支持 `FULL OUTER JOIN`**（可以两个 LEFT JOIN + UNION 模拟）—— 02 图里提过
2. **SQLite 反而支持部分索引**（`CREATE INDEX ... WHERE deleted_at IS NULL`），MySQL 到现在都不支持 —— 第 10 章软删除那招在 MySQL 上要换成"全索引 + 把 deleted_at 拼进键"
3. **PG 的 `RETURNING`** 让"插入后拿自增 id"不用再发一条 SELECT，SQLite 3.35 也有

## 13.7 选型一句话

| 场景 | 推荐 | 理由 |
|---|---|---|
| App/桌面/嵌入式/IoT | SQLite | 零配置、单文件、读性能恐怖 |
| 中小 Web 服务 | PostgreSQL 或 MySQL | MVCC 并发、生态成熟 |
| 复杂分析/地理/JSON | PostgreSQL | 扩展生态（PostGIS/JSONB）无敌 |
| 超大规模写入（日志/埋点） | 专门的 OLAP（ClickHouse） | 行存 OLTP 不适合 |
